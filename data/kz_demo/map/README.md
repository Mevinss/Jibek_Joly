# Stage-one map data

`station_coords.json` and `route_geometry.json` are generated by
`scripts/fetch_station_coords.py` and `scripts/fetch_route_geometry.py`. The scripts copy
the same files to `services/ai/web/assets/map/` for the static frontend.

Station lookup queries OpenStreetMap `railway=station|halt` objects by name within
15 km of each search anchor via Overpass. A unique matching result can be marked
`approximate=false` with its OSM ID. Missing or ambiguous results retain the
previous Railwayz.info-derived generalized coordinate with `approximate=true`.
The search anchor itself is never substituted as a verified location.

Rail geometry is queried from OpenStreetMap `railway=rail` ways, excluding
sidings, yards, spurs and crossovers. A connected snapped shortest path is
marked `geometry_quality=osm_rail`. If the query is unavailable, the existing
AI demo corridor is copied with `geometry_quality=generalized` and
`real_length_km=null`. Demo distances and block fractions always come from the
synthetic `data/kz_demo/KZ` tables. They are not observed rail distances.

OpenStreetMap data: © OpenStreetMap contributors, available under the
[Open Database License](https://opendatacommons.org/licenses/odbl/1-0/).
OpenFreeMap Positron is the optional online vector style. The local fallback
uses the project's existing generalized geometry and Natural Earth country
outline. Generated map data is not operational ҚТЖ information.

As generated in this checkout, all nine stations are approximate and all eight
segments are generalized because Overpass did not return a unique verified
result. Run the scripts again when Overpass is available and inspect each
candidate before treating the result as a verified station or rail alignment.
