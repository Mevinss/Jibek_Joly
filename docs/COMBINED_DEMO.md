# Объединённое демо Jibek Joly

Ветка: `codex/combined-demo`. Главная страница — `frontend/index.html`.

## Запуск

Из корня репозитория, Python 3.11:

```powershell
python -m pip install -r services/ai/requirements.txt
python -m services.ai.main
```

Открыть `http://localhost:8002/`. Node и сборка фронтенда не нужны. Старый процесс после смены ветки необходимо перезапустить. Для отдельного просмотра рядом с ним:

```powershell
python -m uvicorn services.ai.main:app --host 127.0.0.1 --port 8012
```

## Что собрано

- Карта Казахстана, три города, шесть станций, табло 12 SIM-сервисов из командного сайта.
- Интерактивная Three.js-станция: вращение, приближение, вид сверху, выбор поезда. При отсутствии WebGL остаются схема путей и табло.
- Четыре сценария A/B с вычисляемой очередью, диаграммами и прозрачной стоимостью. Средняя скорость подхода проверяет расстояние, время и ограничение; недостижимое окно не выдаёт скорость.
- Игра из четырёх решений с переносом задержек и вычисляемым итогом, дашборд и фильтры причин.
- Диспетчерская с ответами `/demo/snapshot`, `/infra/geometry`, потоком `/demo/stream`, 28 SIM-поездами, расписанием, паузой, историей, CSV и учебным закрытием участка.
- Реальный `/dispatch/analysis` по зафиксированному снимку: FIFO, CP-SAT пары, допустимость и отдельный статус полного плана.
- Проверка прогноза по текущему снимку и версии моделей из API; непроверенные для Казахстана ML-числа не выводятся.
- RU/KK с отметкой о непроверенном казахском переводе, светлая/тёмная тема, узкий экран.

Исходная диспетчерская сохранена на `/dispatch-original.html`; лаборатория — `/lab.html`.

## Сценарий показа, 3–4 минуты

1. Карта → Астана → Астана-1: показать 3D и выбрать поезд на табло.
2. Сценарии → закрытие: сравнить очереди, изменить расстояние подхода и получить недостижимое окно.
3. Игра: принять решение и объяснить накопление задержек.
4. Диспетчерская: 28 поездов из API, закрытие участка, расчёт. Разделить допустимость пары и статус полного участка.
5. Модели и данные: объяснить текущий результат и необходимые реальные данные.

## Границы результата

Это рабочая общая оболочка с двумя отдельными моделями состояния. Карта/игра командного сайта и 28-поездный API не синхронизированы. Решения в игре не меняют API-снимок. 3D — учебная схема; движение, пассажиры и расписание синтетические. CP-SAT пары не применяется к воспроизведению. Полный план может быть `INFEASIBLE`: статус выводится без замены чисел. Скорость подхода — кинематическая иллюстрация без разгона, торможения и оценки энергии.

PKP обучен на польских поездках; Казахстан не валидирован. `rule_fallback` — эвристика. `p_conflict_15m` — старое имя прокси следующего сегмента. KZ-модель изучает длительность расписания, а не задержку. SHAP описывает log-odds до калибровки, не причинность.

## Приоритеты команды на оставшиеся 12 часов

| Участник | Задача | Проверяемый результат |
|---|---|---|
| 1 | Проверить демонстрацию, RU/KK, доступность и размеры экрана | Полный показ без обрывов |
| 2 | Исполнение выбранного плана на одном учебном участке | Снимок → допустимый план → наблюдаемое исполнение; не заявлять все 28 без проверки |
| 3 | Доказательства по моделям и данным | Источники, границы данных, воспроизводимая оценка |
| 4 | Питч, видео и резервный локальный запуск | Короткая история проблемы и показ без интернета |

Сначала пройти показываемый сценарий всей командой. Затем интегрировать один участок; последние два часа оставить на проверку и репетицию. Новые несвязанные панели добавлять после этого.
