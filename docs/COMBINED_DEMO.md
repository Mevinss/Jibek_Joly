# Демо Jibek Joly — диспетчерская участка

Ветка: `codex/combined-demo`. Главная страница — `frontend/index.html`. Последняя правка заменяет набор независимых экранов одной диспетчерской: поездограмма, карта и 3D используют один снимок и одну историю.

## Запуск

Из корня репозитория, Python 3.11:

```powershell
python -m pip install -r services/ai/requirements.txt
python -m services.ai.main
```

Открыть `http://localhost:8002/`. Node и сборка фронтенда не нужны. Уже работающий сервер нужно перезапустить после смены ветки. Отдельный локальный просмотр:

```powershell
python -m uvicorn services.ai.main:app --host 127.0.0.1 --port 8012
```

## Что работает

- Все 9 станций из `main`: Көкшетау-1, Курорт-Бурабай, Ақкөл, Астана-1, Қарағанды, Ақадыр, Сарышаған, Шу, Алматы-2. Занятость путей берётся из снимка.
- 28 SIM-поездов, один SSE-поток 1 Гц, пауза, ×1/×10, сброс, события, перемотка до 15 минут и CSV.
- Поездограмма сверху: расписание с остановками, фактически записанное движение, пунктир продолжения с текущей скоростью. Станции разнесены по вертикали; расстояния между строками не означают географический масштаб. Выбор участка и поезда, управление клавиатурой.
- Карта Казахстана без внешних тайлов и настоящая Three.js-станция: камера, вид сверху, выбор поезда. Все SIM-идентификаторы и позиции — из того же снимка. Путевое размещение в 3D условное: точных путевых позиций в источнике нет.
- Рекомендательная средняя скорость до следующей станции вычисляется из расстояния, времени и ограничения скорости. Закрытие, ожидание и недостижимое расписание не получают назначенную скорость. Разгон, торможение и энергия не моделируются.
- Индекс 0–100 с раскрываемыми факторами: задержки, закрытие, остановившиеся поезда, ограничения, переполнение станции. Блоки с несколькими поездами показаны отдельно; этот фактор и энергия не входят в формулу.
- Реальный `/dispatch/analysis` автоматически проверяет CP-SAT пары каждые 30 секунд и после события. Показывает ресурсы и время резервирования. Статус всех 28 поездов выводится отдельно. Ограничение скорости и каскад пока не поддержаны решателем.
- RU/KK, светлая/тёмная тема без сброса времени и истории, адаптация к узкому экрану, восстановление связи с сохранённого времени, переходы по ссылкам и «Назад».

Модель, игра, сценарные A/B-панели и дашборды удалены из главного интерфейса. Исходные страницы доступны на `/dispatch-original.html` и `/lab.html`; их наличие не означает, что они входят в текущий показ.

## Показ за 3 минуты

1. Выбрать SIM-поезд на поездограмме: показать расписание, записанную траекторию и текущую позицию. ×10 ускоряет демонстрационное время, частота потока остаётся 1 Гц.
2. Открыть любую из 9 станций: показать 3D и табло того же потока.
3. Закрыть участок у Ақкөл: показать остановку, отсутствие рекомендации скорости и вычеты индекса.
4. Показать проверенный план пары и отдельный статус всех поездов; не выдавать план пары за решение всего участка.
5. Пауза → история → прямой эфир → CSV. При обрыве серверной связи позиции замораживаются.

## Соответствие кейсу и остающийся объём

| Требование | Текущее состояние |
|---|---|
| Реальное время / разрешённый mock ≥1 Гц | SSE синтетических данных, обработка дубликатов и устаревших кадров, reconnect с backoff |
| Топология, расписание, карта, поездограмма | Геометрия 9 станций / 56 блоков и расписание 28 поездов из backend |
| Перепланирование без конфликтов | Реальная проверка пары; полный план 28 поездов не подтверждён и не исполняется |
| Рекомендательный профиль скорости | Упрощённая средняя скорость подхода; физический ATO-профиль и энергия остаются задачей |
| Прозрачный индекс | 5 показанных факторов, формула демонстрационная; перекрытия блоков отдельно |
| События и история 5–15 минут | 4 режима события, история до 15 виртуальных минут, CSV |
| Сигналы, стрелки, PDF, задержка интерфейса <500 мс | Телеметрии сигналов/стрелок и PDF в этом интерфейсе нет; приёмочный замер производительности не выполнен |

## Приоритет команды из 4 человек

1. Планирование: добиться допустимого плана на одном участке и связать его исполнение со снимками. Затем расширять; не обещать все 28 заранее.
2. Профиль движения: ограничения, разгон, торможение, остановки и проверяемая модель энергии.
3. Интеграция: сигналы/стрелки, валидация и журнал, PDF, замеры скорости обновления.
4. Показ: пройти полный сценарий, проверить перевод, подготовить короткое видео и резервный локальный запуск.

Новые панели добавлять после прохождения основного сценария. Последние два часа оставить на проверку и репетицию.

## Границы данных

Это рекомендательный hackathon demo, не управление поездами. SIM-данные и географические маршруты только Казахстан; это не оперативные данные ҚТЖ. Продолжение линии — экстраполяция скорости, не оптимизированный план или ML-прогноз. План пары не меняет воспроизведение. 3D — схема, не цифровой двойник точной путевой геометрии.

ML не участвует в этом экране. PKP не валидирован для Казахстана; `rule_fallback` — эвристика; `p_conflict_15m` — старое имя прокси следующего сегмента. KZ-модель изучает длительность синтетического расписания, не задержку; SHAP описывает log-odds до калибровки, не причинность.
