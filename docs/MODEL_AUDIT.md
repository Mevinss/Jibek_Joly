## 2. Риск и 2,2% перед закрытием
Исходная метка: delta_delay>=3 ИЛИ difficulty_id в [5,6,7,34,36,39]. Нельзя честно переименовать существующее поле только в вероятность роста >=3. Порог 0.10363247863247864, isotonic на половине validation-run IDs, порог F2/recall>=0.7 на другой половине. Test Brier 0.0361367, ECE 0.00127874 (10 равных bins). Малый ECE при редком событии не означает хорошую полноту/точность каждого алерта. Показанные 10.31 мин = текущая задержка + предсказанный delta; 2.2% = калиброванный legacy proxy. Нет длительности будущего закрытия и нет гарантии переноса.

## 3. Инциденты
closed и speed warning учитываются как флаги только текущего блока; active_disruption_group есть, но симулятор его не заполняет. Нет явного конца закрытия и информации о следующем блоке. Сбой сигнала из infra.signals напрямую в модель не попадает. Исправление требует детерминированного слоя перед ML и отдельной семантики риска.

## 4. Утечки
Официальный split по run_id с assert непересечения. prev_delay наблюдается до прогнозируемого участка, восстановленные значения исключены. stop_order нужен для соединения/порядка, не признак. difficulty_id входит в target, не FEATURES. edge_active_difficulty_id входит через группу: время доступности исходных incident records не подтверждено; ретроспективная утечка через момент регистрации остаётся риском, причинность не заявляется. Исторические статистики для train OOF по run_id, для val/test только train. Абсолютные даты не опубликованы, есть месяцы 3/4/5.

## 5. Бейзлайны
Общий test MAE: модель 0.585917, ноль 0.653228, P50 перегона 0.647147 мин. Бакеты по предыдущей задержке; воспроизводимый расширенный расчёт и численные результаты будут добавлены до сдачи, не заполняются предположениями.

## 6. Единицы и перенос
Регрессия предсказывает абсолютный delta в минутах, не долю времени. Затем delay+delta ограничен снизу нулём. Масштаб учитывают min_technical_time/time_reserve, но KZ использует синтетические блоки и общий профиль — явный domain shift. Данные за пределами train bounds должны помечаться OOD; наличие внутри диапазонов НЕ доказывает отсутствие domain shift.

## 7. KZ
128 синтетических межстанционных примеров, split 15/6/7 полных поездов (67/29/32 строк). Признаки: distance_km, speed_limit_kmh, category_code, destination_tracks, direction. ID не входит, но уникальная длина позволяет узнавать перегон. MAE 0.566 на знакомых сегментах против 38.245 на SHU-ALM подтверждает слабую экстраполяцию, но само по себе не доказывает буквальное запоминание всех строк. Формула генератора не найдена в CSV. Проверим физический бейзлайн и остаток через GroupKFold по segment_id; старую модель сохраним как отрицательный учебный пример.

## 8. Солвер
Реального CP-SAT в исходной ветке нет. Fixture what-if не является расчётом. Нужен контракт optional duration_buffer_s = k*max(0,P90-P50)*60, valid только для проверенного домена и конечных квантилей. Для OOD автоматический буфер отсутствует; безопасный запас выбирает платформа. Учебные сравнения обязаны использовать один seed/снимок и честно обозначать отсутствующий CP-SAT.

## 9. Версия и скорость
pkp-main-298694c, n_jobs=1 на inference. Предсказания детерминированы при одном State и артефакте. training random_state=42. Прежний локальный 25-train HTTP p95 6.80мс, compute p95 4.23мс. Текущий p50/p95 будет измерен отдельно; это не network latency и не SLA.

Формула проверки — линейно подогнанный физический ориентир L/v_limit плюс свободный член/категория/направление; это не восстановленный генератор и не идентифицированные физические разгон/торможение. Два fold ухудшаются с остатком, два улучшаются. Автоматическая замена старой модели такой моделью не принята; прежний KZ endpoint сохранён для совместимости, главный экран больше не подаёт его как полезный прогноз. Формула t=L/vср + потери + стоянка показана как ориентир с демонстрационными параметрами. Для физически точного расчёта нужны профиль пути, ограничения, масса/ускорение и измеренная скорость.

Закрытие в симуляторе конечное: incident_at+1500s. Известное ожидание отдельное, nonnegative, движение возобновляется. Буфер солвера k*(P90-P50) настроен в config/advisory.yaml; для KZ null. Одна и та же synthetic snapshot функция обслуживает карту, поездограмму и карточки.
