# JibekJoly reference demo

Integrated into `main` from `codex/jibekjoly-eco-demo`. The entry point is `frontend/index.html`.
The team's current website source is preserved in `services/ai/web/jibekjoly`;
provenance is recorded in its `SOURCE.md`. The former combined workspace remains
available at `/combined/` and the old dispatcher at `/dispatch-original.html` (also `/legacy`). The team runtime dashboard and its APIs remain at `/dispatch-dashboard.html`.

## Run and present

Use Python 3.11, install `services/ai/requirements.txt`, and run
`python -m services.ai.main` from the repository root. Open `http://127.0.0.1:8002/`.
No Node build is needed. Node is used only for development checks and fixture export.

1. On **3D-коридор**, select **SIM-FRT-208**. It starts halfway between Астана and
   Қарағанды: 7 model km remain, the next main-track signal opens at 08:10,
   the limit is 80 km/h, and the mean target is 42 km/h. The smooth profile decelerates from 80 to about 38.7 km/h, then cruises to the green window.
2. The train card has the speed profile and a predicted `full stop avoided` badge.
   Run the simulation; the confirmed badge counts advised passages actually made on green without stopping. This passage count is distinct from the paired-run stop difference. Turning Eco off uses
   the ordinary speed and causes a stop in this example.
3. Click a station in 3D or choose one on the arrival board. The board simulates a
   copy of the exact current snapshot, including occupancy and known restrictions.
   Text and colours distinguish ≤5, >5–15 and >15 minutes of delay. A held train's
   future ETA can be unknown. Future untriggered incidents are excluded.
4. Open **Сценарии**, choose a case and press **Итог**. Each side receives the same
   train package and the same incident block/time. The managed side uses repair,
   reserve, priority and Eco; it is not a controlled experiment isolating Eco alone.
5. **Поездограмма и план** compares six policies in a Web Worker. An outdated or
   archived plan cannot be applied to the current trip. History, profile charts,
   CSV and PDF use the selected trip; archived Eco controls are disabled.

## Data and limits

`kz-eco-synthetic-v2`, seed 20261002, contains six SIM trains with speeds,
mass, scheduled release times, an initial position and a known signal window.
Nine Kazakhstan station names follow the team reference. Distances, topology and
schedule are compressed demonstration inputs, not operational ҚТЖ data.

Eco advice integrates a speed ramp and cruise to a known opening. Freight acceleration is 0.10 m/s² and deceleration is 0.12 m/s²; passenger rates are 0.25/0.30 m/s². These are synthetic parameters, not validated braking curves. All train types check the shared directional signal before entering a block. Manual red, occupancy, headway and known restrictions take priority. Unknown openings, a closed
current block, unreachable windows and required speeds below 5 km/h do not produce
an actionable target. Advisory availability and confirmed simulation stop avoidance
are distinct. Terminal arrival is excluded from intermediate stop counts.

The mass/speed/idle proxy uses arbitrary units and charges positive squared-speed changes. Final fuel results convert it using an explicitly uncalibrated 0.4 litres per proxy unit. They are synthetic estimates, not measured diesel consumption. Two full counterfactual runs use identical initial input, signal windows, observed incident placement/time and dispatcher commands, varying only Eco. Savings remain signed. The five-factor movement index uses lateness against a fixed feasible schedule, unplanned queues, signal compliance, opposite-route conflicts and schedule arrival deviation. The schedule is generated by `scripts/export-wave-timetable.mjs`, not moved after incidents or user commands. The index is a heuristic, not ML accuracy. The
existing PKP forecaster and Kazakhstan synthetic schedule model remain separate.
The new UI does not silently show unrelated fixture forecasts or ML results.

Live motion here is a browser simulation. `/eco/advice` computes on submitted inputs;
the card's server-check button pauses playback and confirms the captured snapshot
or shows a request error. This interface does not claim to consume ҚТЖ telemetry.
Unreviewed Kazakh translation is marked in the UI.

## Green-wave presentation

The map starts in an incident-free synthetic two-direction corridor. The earlier crowded corridor remains selectable and is still used for the comparison/game scenarios. Sixteen visible signals derive from the same gating logic as train entry. Click a signal in 3D or the signal board to toggle a manual red; click again to restore automatic aspect. A known opening is never promised for an occupied block or a manual red.

A healthy full run reaches 100/100 with zero timetable lateness. Both freight trains cross four advised greens without intermediate stops. In the paired whole-trip experiment, ordinary driving incurs three stops each. Actual computed synthetic fuel: SIM-FRT-208 69.7331 → 40.2522 litres (29.4809 saved); SIM-FRT-209 65.6262 → 45.7945 litres (19.8318 saved). These numbers are evaluation evidence; the UI recomputes its comparison. Disruptions/holds can lower the index and change savings.

Click **Показать итог поездки** to simulate the remaining trip immediately. It does not remove manual reds or holds; an unfinished run has no claimed fuel saving. Archived frames preserve their own manual signal state, station passages and action history.
